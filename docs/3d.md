# The 3D view

Hubbub has two views of the same game, chosen on the join screen (or with `?view=2d` / `?view=3d` in the address): a flat 2D map drawn with Phaser, and a 3D town drawn with three.js. Everything that matters is shared: the generated world, collision, chat, voice, screen sharing and the network do not know which view is in use.

## How it is organised

```
GameController  (app/src/game/GameController.ts)   movement, places, chat, voice, sharing, test hooks
      |
      |  Renderer interface (app/src/game/renderer.ts)
      |
      +-- PhaserRenderer (game/phaser/)   the 2D view
      +-- ThreeRenderer  (game/three/)    the 3D view
```

Positions are always world pixels (32 per tile), the same numbers the network carries; the 3D view divides by 32 to get world units (one tile is one unit, roughly a metre).

Only the renderer in use is downloaded (about 144 KB gzipped for 3D, 344 KB for 2D).

## What the 3D view does

- **Town:** each 32 x 32 tile square becomes four merged meshes (ground, lit things, glowing things, light pools), so a square costs a few draw calls. Squares within two of you are loaded, the nearest ring immediately and the rest one per frame; far ones are freed. Trees, lamps, benches, fountains, market stalls and pitched-roof buildings with lit windows and recessed two-tile doorways.
- **Buildings:** the same generated interiors, with walls low enough to look over, tables, a bar, barrels, shelves, a rug, hanging lamps and a screen on the back wall.
- **People:** a robed figure built from simple solids using the same look (kind, hat, robe, skin, extra) as the 2D picture, with a name tag, speech bubble, speaking ring, walking sway and turning to face where they walk.
- **Camera:** third person, orbiting the player. Drag (or right-drag) to turn and tilt, scroll or pinch to zoom, Q and E to rotate. Movement keys are relative to the camera: forward is away from it. Click or tap the ground to walk there. Indoors the camera stays high enough to look over the walls and is framed between you and the middle of the room so the screen stays in view.
- **Wall screen:** a shared screen is a live video texture on the back wall; the theatre view is unchanged.

## Replacing the placeholder art

The 3D town is built from boxes, cones and cylinders. To use a proper model kit (for example Kenney's CC0 3D town and character kits):

- Town: replace `game/three/chunkMesh.ts` (`buildChunkGeometry`) and `interiorMesh.ts`. They read the same tiles and buildings, so only how things look changes.
- People: replace `game/three/avatarMesh.ts` (`buildAvatarModel`). Keep the returned `group`, `arms`, `body` and `height`, or adapt the small animation code in `ThreeRenderer.updateAvatars`.
- Record licences in `docs/ASSET-CREDITS.md`.

## Testing

- Geometry builders and the camera maths are pure and unit tested without a GPU (every kind of square, every building interior, every avatar combination).
- The browser suites run against both views: `cd e2e && npm run test:2d` and `npm run test:3d`. They use software rendering, so 3D tests use smaller windows and run at roughly 8 frames a second when several browsers share one CPU.

## Known limits

- Placeholder art only; it has not been looked at on a real GPU, a phone or a high-density display.
- Buildings can hide the player when the camera is low and close to one; rotate or raise the camera.
- No shadows (a soft blob under each person instead) and no ceiling in interiors, to keep it light and the room visible.
- Phones default to the 2D view; 3D works there but has not been tuned for battery or small screens.
